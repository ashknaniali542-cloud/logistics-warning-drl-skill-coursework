# 文献依据、开源借鉴与创新定位

## 从问题扩展检索，而非只搜算法名

将问题拆成业务对象、决策动作、时间/资源约束、数据特征和优化目标。中英文分别检索，按三层建立证据：

1. **直接任务层**：该领域如何处理相同业务问题，例如配送延误、流程监测、早期预警。
2. **相邻决策层**：相同决策结构在其他领域如何建模，例如早期分类、最优停止、约束决策。
3. **算法机制层**：实际准备实现的DQN、PPO、价值分解或预算反馈的原始论文。

预警问题可组合“delivery delay warning / alarm-based process monitoring / early classification / optimal stopping / false-positive budget / lead time”；调度问题则换成资源分配、约束和动作可执行性。关键词由当前任务生成，不固定沿用物流术语。

优先阅读论文原文、作者代码、期刊或会议页面、行业官方文件。搜索摘要用于筛选，关键机制回到方法节和实现。记录作者、题目、年份、出处、版本、DOI/URL及实际阅读范围。综述用于建立地图，最终算法细节尽量引用原始来源。

## 文献比较表

| 字段 | 应回答的问题 |
|---|---|
| 问题与业务目标 | 解决预测、触发时机、调度还是控制？ |
| 数据与观察条件 | 静态/事件序列？规则采样/不规则？完整/部分可见？ |
| 动作与环境 | 动作是否改变真实未来？回放或模拟如何成立？ |
| 核心机制 | 神经网络和RL目标分别在哪里？ |
| 评价口径 | 分母、预算、窗口、成本和数据划分是什么？ |
| 对照与代码 | 简单及强基线是否可复现？代码是否真对应论文？ |
| 迁移条件 | 本数据能满足哪些前提，需要哪些适配？ |
| 借鉴内容 | 借状态、目标、观察机制、训练、评价还是实现？ |

不要把“别人用过”写成当前数据有效的证据。也不要把“没人用完全相同的缩写”作为新颖性证明。

## 创新的可检验表达

采用“已有方法的适用条件—本任务的差异—具体机制—对应实验”的结构。可以是任务形式化、观察协议、动作表示、约束参与方式或计算/信息组织的改进，不限定为新增网络模块。

示例：已有触发策略在离散前缀上决策；当前订单存在由到货期限和处置窗口确定的绝对边界；增加该边界的可见状态；在固定网络和预测器下，以等更新量及同信息对照检验增益。

保留经典PPO/DQN作为基线并不影响贡献辨识度。为了使用新名称而机械替换经典学习器，通常无法改善问题与方法之间的逻辑。能复现的机制和可信对照比模块数量更重要。

## 开源项目的选择性使用

检查论文对应版本、维护者、许可证、依赖、输入输出、训练与评估协议、已有测试和代码实际实现。先读再运行。借鉴范围记录为直接复用、任务适配、独立对照或候选想法；保留版本和引用。

外部代码默认参数不自动成为本项目合理参数。课程项目优先选择可在已有数据与资源上完整复现的机制，不为了使用仓库而扩大问题或新增没有依据的环境规则。

## 国内外综述与引文落点

用户要求按国内外划分时，每部分内部仍按问题脉络组织。每个引用说明支持的是业务背景、算法机制、数据处理、评价方法还是比较结果。国内论文不只补数量；国外经典论文不替代国内实际应用研究。最后用文献评述把两部分收束到本研究切入点。
