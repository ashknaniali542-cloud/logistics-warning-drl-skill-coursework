# 从实际问题设计研究

## 用决策句替代算法口号

先写一句可验证的问题：

> 对于【业务对象】，在【当时可见信息】下选择【动作】，在满足【时间、容量、安全或费用约束】的条件下，提高【主要业务收益】。

预警案例：在事件信息逐步更新时选择等待或首次报警，在保留处置提前量并控制正常记录误报的条件下，提高延误及时覆盖。

调度案例：在车辆位置、电量和订单到达信息可用时决定任务分配，提高有效服务量，并满足电量及资源互斥约束。此任务需要调度动作、状态演化和资源规则的依据；只有订单结果表时，先检查是否具备这些条件。

## 先盘点数据，不先构造环境

逐表记录统计单位、行数、主键、时间范围、字段语义、缺失、实体关联和可用时点。分开统计原始行、有效实体、轨迹、观察状态及训练转移。大表不自动构成大规模独立样本。

| 问题 | 需要的证据 | 缺少时的处理 |
|---|---|---|
| 能否按时间读取状态？ | 事件/入库时间、计划版本或明确可见性规则 | 采用有依据的可见性情景并检验敏感性 |
| 动作是否真实存在？ | 历史动作日志、业务规则或可验证仿真 | 转向数据支持的决策问题 |
| 动作能否改变后续结果？ | 转移规律、干预记录、可信模拟器 | 不用历史原路径替代干预后的反事实 |
| 多表能否关联？ | 有效键、时间一致性、唯一性 | 分别说明用途，保留不能逐条关联的来源 |
| 成本/容量从何而来？ | 企业资料、原始论文、行业规则或数据估计 | 标为研究参数，做合理范围敏感性 |

每个设定登记来源类型：数据事实、外部规定、论文方法、业务确认、研究情景。引用某标准的服务质量要求，不自动赋予自选提前量或误报阈值行业效力。

## 深度强化学习成立条件

- **决策过程**：状态/历史、动作、转移或观察更新、奖励、终止条件与决策频率明确。
- **长期关系**：当前动作与后续机会或累计收益有关。一次分类后套阈值通常仍是监督预测规则。
- **神经近似**：神经网络实际学习策略或价值，参数由Bellman目标、策略梯度等序贯目标更新。
- **执行闭合**：训练得到的策略确实输出动作并接受同一业务目标的评价。

“LightGBM预测＋神经Q网络学习报警/等待”可以构成DRL系统；预测器不必也是神经网络。表格Q学习是RL；监督训练的MLP是DL；加入神经网络图并不能替代实际的DRL训练。

预警回放的特殊性：若报警只终止观察、等待只揭示下一段既有信息，可以在明确该边界下构造停止问题。若动作改为换仓、补货、催运、加车，则重新检查行动后果。把停止回放迁移成调度模拟需要额外证据。

## 创新从错配中产生

依次诊断：业务目标与训练奖励是否一致；关键时点是否被观察；状态是否包含当时可用信息；动作表示是否符合业务；约束是否只在事后修剪；训练反馈是否有必要。

每项候选填四行：

1. 现象：数据或对照中出现了什么具体问题？
2. 机制：改动哪一部分，为什么能针对这个现象？
3. 验证：控制哪些因素，用什么对照识别它的作用？
4. 决定：什么结果支持保留、简化或放弃？

优先选择可实现、可解释、有明确对照的机制。相同网络下改善观察协议可以是有意义的方法贡献；复杂网络没有改善时，保留较简单实现及消融证据。

## 研究推进与转向

先做能检验核心假设的小规模诊断，再运行约定的全量数据。小样本结论要记录范围；全量处理也要报告实际参与各阶段的数量。

表现不好时按顺序检查：指标/分母 → 可见性与标签 → 观察机会 → 简单强基线 → 奖励/约束 → 优化器和训练 → 网络容量。不要把所有失败归因于预测器，也不要靠更换模型名称延长无依据的方向。

方向转变时写出“旧问题需要的证据、现有数据能提供的证据、新问题如何闭合”。保留原始结果，避免把早期失败描述为从未发生。
